## Overview

The `packages/ai/src/types.ts` module defines the core type system for the AI package, establishing the contracts for provider interactions, message structures, and API capabilities. It serves as the single source of truth for the shapes of requests, responses, and configuration options used by the various provider adapters.

This section details the exported interfaces and types that govern how the package communicates with upstream AI services. It covers the uniform stream contract, the message event protocol, and the specific compatibility settings for different API implementations, ensuring type safety across the provider layer.

## Example

The `AssistantMessage` type aggregates the final result of a stream, including usage and diagnostics.

```ts
export interface AssistantMessage {
  role: "assistant";
  content: (TextContent | ThinkingContent | ToolCall)[];
  api: Api;
  provider: ProviderId;
  model: string;
  responseModel?: string;
  responseId?: string;
  diagnostics?: AssistantMessageDiagnostic[];
  usage: Usage;
  stopReason: StopReason;
  deferred?: DeferredHandle;
  errorMessage?: string;
  rawStopReason?: string;
  endTurn?: boolean;
  timestamp: number;
}
```

## Notes

- The `AssistantMessageEvent` union type defines the event protocol for `AssistantMessageEventStream`, emitting `start` before partial updates and terminating with `done` or `error`.
- `AssistantMessage` includes a `deferred` field of type `DeferredHandle` to support best-effort deferred-response cancellation.
- `ToolResultMessage` carries `addedToolNames` to indicate tools that became available after the result, which providers with native deferred tool loading use as the load point.
- `SimpleStreamOptions` includes a `purpose` field to mark one-shot maintenance requests, allowing providers to namespace the prompt cache.
- `OpenAICompletionsCompat` provides compatibility settings for OpenAI-compatible completions APIs, including `thinkingFormat` and `chatTemplateKwargs` for reasoning control.

# Why a Fork?

`bramburn/qi` began as a fork of [earendil-works/pi](https://github.com/earendil-works/pi) and is now maintained as an independent project. This page explains the origin and the constraints that shape it.

## Motivations

### Build and publish autonomy

The upstream project owns its domain, its npm scope, and the CI pipeline that publishes to both. As a solo developer using the agent heavily, the author wanted:

- **Independent npm publishing** — releases publish to `@bramburn/*` and do not depend on another project's pipeline
- **Independent binary distribution** — every release is self-contained on GitHub releases
- **Faster iteration** — changes can be built, tested, and released without an external review step

### Windows-first development

The author develops on Windows. The build pipeline and CI cover Windows explicitly, and the development workflow assumes a Windows/PowerShell environment where relevant.

### Project-specific features

Some features exist because the author needed them and would not fit another project's roadmap (for example the `validateLlmMessages` guard, the `build-both` orchestrator, and the `FORK_NAME` constant in version output).

## Relationship with upstream

The project is **severed** from upstream. It does not merge upstream releases, does not link to upstream documentation, and does not call upstream network endpoints. See `specs/adr/0002-sever-upstream-endpoints.md` in the repository.

| Aspect | qi |
|--------|-----|
| npm scope | `@bramburn/*` |
| Command | `qi` |
| Configuration | `~/.qi` and `.qi/` |
| CI runtime | **Bun** |
| Releases | GitHub releases + npm |
| Issues | [bramburn/qi issues](https://github.com/bramburn/qi/issues) |

The project is MIT-licensed, same as the code it started from.

## Contributing

Issues and PRs go to [github.com/bramburn/qi](https://github.com/bramburn/qi). See the main [CONTRIBUTING.md](https://github.com/bramburn/qi/blob/main/CONTRIBUTING.md) for the contributor workflow.

Changes are not proposed upstream: the repository maintains its own version line and its own review process.

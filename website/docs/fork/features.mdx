# Fork Features

Feature notes for `bramburn/qi`. The project is severed from the upstream `pi` project (see [Why a Fork?](./why-fork)), so this page describes qi on its own terms.

## Runtime support

| Runtime | Role |
|---------|------|
| Bun | **Primary** (install, build, check, test, scripts, shebangs) |
| Node.js | Legacy (`npm publish` for OIDC; `package-lock.json` regeneration; `npm-shrinkwrap.json` for downstream consumers) |
| Test runner | vitest runs under bun-launched node via shebang; root `test:scripts` uses `bun test`; `packages/tui` and `packages/clipboard-rs` keep `node --test` (intentional split) |

The project has completed a Helix-style migration to bun across the source tree:

- All root `package.json` scripts (`build`, `build:offline`, `clean`, `check`, `test`, `eval`, `generate:models`, `prepublishOnly`, `publish`, `release:*`, `version:*`) launch under bun.
- All workspace `package.json` scripts (`build`, `prepublishOnly`, etc.) launch under bun.
- All 21 `scripts/*.mjs` shebangs are `#!/usr/bin/env bun`.
- CI workflows (`ci.yml`, `docs.yml`, `build-binaries.yml`, `issue-analysis.yml`) use `oven-sh/setup-bun@1.3.14` and `bun install --ignore-scripts --linker=hoisted`.
- `engines.bun: ">=1.3.14"` declared in all 10 `package.json` files.

The remaining `npm` calls are intentional and required:

- `npm publish --provenance` (per-package, in `scripts/publish.mjs`) — OIDC trusted publishing requires npm CLI ≥11.5.1; bun's `bun pm` does not support OIDC.
- `npm ci --ignore-scripts` (in `scripts/build-binaries.sh`) — regenerates `package-lock.json` (bun writes `bun.lock`).
- `npm install --prefix … --include=optional` (cross-platform native clipboard deps) — bun's `--force` does not match npm's cross-platform optional-deps semantics.
- `spawnSync('npm.cmd', ['view', …])` (in `scripts/release.mjs:61`) — npm-registry introspection.

See [Runtime support in the README](https://github.com/bramburn/qi/blob/main/README.md#runtime-support) for the full picture.

Local development uses bun:

```bash
bun install --ignore-scripts --linker=hoisted # primary
bun run build # primary
bun run check # primary
bash ./test.sh # primary (bun run test:scripts && bun run --filter '*' test)
```

Legacy npm paths still work but are no longer recommended:

```bash
npm install --ignore-scripts # legacy
npm run build # legacy (chained through bun; see scripts/)
```

## Fork identity constant

`packages/coding-agent/src/config.ts` exports `FORK_NAME = "bramburn"`. This appears in `qi --version` output:

```
qi 0.84.2 [bramburn]
```

The fork identity is intentional: it identifies the `@bramburn/*` build.

## `validateLlmMessages` guard

The project adds an explicit guard in the message loop that validates `user` and `assistant` messages before sending them to the LLM. Invalid messages (e.g., empty content, malformed tool calls) throw rather than being silently sent.

## Build tooling

The repository uses a custom `build-both` orchestrator (`scripts/build-both.mjs`) that:

- Detects Node.js and Bun on `PATH`
- Runs each build target independently
- Reports `BUILT / SKIPPED / FAILED` per target
- Supports `--node-only`, `--bun-only`, `--clean`, `--quiet` flags

The orchestrator replaces per-target scripts with a single entry point.

## tsgo via Bun

The build invokes `tsgo` (TypeScript-to-Go compiler) via `bun run` directly:

```bash
bun run node_modules/@typescript/native-preview/bin/tsgo.js -p tsconfig.build.json
```

Other TypeScript-to-Go setups invoke the binary directly.

## `qi-bun` wrapper on PATH

On Windows, the project ships a `qi-bun.cmd` wrapper at `C:\Users\<user>\.qi\agent\bin\` that calls `packages/coding-agent/dist/qi.exe` directly. This lets `qi-bun --version` work from any directory without `cd`-ing into the repo.

## Notable features

- **Background subagent mode** — `subagent({ background: true, ... })` spawns a detached child `qi`, returns a task ID immediately, and injects the result as a `subagent-background-result` custom message on the next turn. Respects `agentScope` and the project-agent trust prompt the same way foreground mode does. File-locked registry at `<agentDir>/subagent-bg/` survives parent restarts. See [Background Subagent Mode](./background-subagent) for the user guide and [Background-Task Architecture](/docs/architecture/background-tasks) for the internals.
- **`validateLlmMessages` guard** — explicit validation of `user` and `assistant` messages before sending to the LLM (see above).
- **`build-both` orchestrator** — `scripts/build-both.mjs` runs the Node and Bun build targets independently and reports per-target status (see above).
- **`FORK_NAME` constant** — `packages/coding-agent/src/config.ts` exports `FORK_NAME = "bramburn"` so the build is identifiable in `qi --version` output (see above).

## Planned features
